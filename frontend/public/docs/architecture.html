3. Đối chiếu System Context Diagram (proposal §12)

Proposal mô tả hệ thống trung tâm + 4 actor bên ngoài. Bảng dưới ánh xạ từng actor → thành phần thật trong code:

Actor trong proposal §12 Đưa vào hệ thống gì Nhận lại gì Cài đặt ở đâu
Individual User Origin, Destination, Vehicle type, Travel time, Trip purpose, Preferences Route, Distance, Travel time, LEZ status, Vehicle compliance, Air quality, Recommendations, Option comparison Form trong planner.tsx gửi đúng 6 trường này → POST /api/trip/analyze trả về đủ 8 nhóm thông tin (route geometry, distance/duration, LEZ status outside/partial/within, compliance per mode, AQI, ranked recommendations, comparison, impact)
System Administrator LEZ areas, Policy rules, Vehicle restrictions Transportation trends, Regional analytics, Switching patterns, Policy analytics admin-dashboard.tsx: LEZ Zones CRUD + Policy Rules CRUD + Modes & Weights → routers/admin.py; 4 nhóm analytics đọc từ GET /api/admin/analytics (trend theo mode, phân bổ theo quận, switching rate, KPI chính sách)
Map & Routing Service Origin, Destination, routing options Route geometry, Distance, Estimated time, map data Nominatim (geocode) + OSRM FOSSGIS/demo (route) qua services/external.py; cache RAM 30' + fallback ước lượng (đúng mitigation "Map/routing API unavailable" của §13)
Air Quality Service Location/coordinates, time range AQI, pollutant info, measurement time, status Open-Meteo Air Quality qua services/airquality.py; cache DB 30' + hiển thị update time + mô phỏng dự phòng (đúng mitigation "Air quality API failure" của §13)

Điểm proposal nhấn mạnh — "OSRM only performs route calculation. The determination of whether a route intersects with an LEZ is handled separately by RideShift through a PostGIS Spatial Query within the system's internal architecture" — được cài đúng: OSRM chỉ trả polyline; việc outside/partial/within được quyết định bởi lớp không gian nội bộ (services/geo.py): Shapely trong sandbox, PostGIS trong deployment Docker.

4. Luồng xử lý chính — POST /api/trip/analyze

  1. Geocode origin/destination (Nominatim + fallback local list).
  2. Route (OSRM): distance, duration, polyline ~370 điểm; cache RAM 30 phút; nếu cả 2 provider hỏng → synthetic route + cờ source: 'estimated'.
  3. LEZ spatial: polygon từng lez_zones.geometry (PostGIS MULTIPOLYGON, đọc qua ST_AsGeoJSON — db.geom_read) so route vs zone → outside | partial | within + % chiều dài trong zone (Shapely sampling).
  4. DB-level: cột geometry + GIST index sẵn sàng cho truy vấn không gian trực tiếp (ST_Intersects / ST_DWithin…) đúng DB FINAL workflow.
  5. Compliance: quét policy_rule theo zone×mode (banned/conditional, giờ, ngày trong tuần, điều kiện Euro standard).
  6. Air quality: AQI theo tọa độ (cache bảng air_quality_cache, TTL 30').
  7. Trend criterion: bảng dataset_trend do pipeline pandas tạo (fallback TREND_PRIOR).
  8. TOPSIS (mcdm.py trên numpy): 7 tiêu chí × 7 mode, trọng số từ criteria_weight (25 travelTime / 20 cost / 20 lezCompliance / 10 accessibility / 10 convenience / 10 environment / 5 trend); cost-type criteria (travelTime, cost) đảo chiều benefit chuẩn TOPSIS.
  9. Persist trip_record (top mode, score, LEZ flag, chi phí/thời gian trung bình).
  10. POST /api/trips/{id}/choice ghi chosen_mode_id + switched → nguồn liệu cho KPI "switching intention" của admin.

7. Rủi ro §13 → biện pháp đã cài trong kiến trúc

Rủi ro (proposal §13) Mitigation trong code
Map/routing API unavailable (High) Provider chain FOSSGIS → OSRM demo → synthetic; cache RAM 30'; cờ estimated trên UI
Air quality API failure (Medium) Cache DB TTL 30' + hiển thị fetchedAt + mô phỏng dự phòng
LEZ policy changes (High) LEZ zones/rules CRUD runtime qua admin API, không cần redeploy
Recommendation inaccuracy (Medium) Trọng số 7 tiêu chí chỉnh được + sum=100 validation; top-k + breakdown từng tiêu chí
Spatial data processing errors (Medium) 3 trạng thái outside/partial/within test được; dual-mode PostGIS/Shapely
External API changes (Medium) External services gói trong services/external.py (một lớp duy nhất)
Security vulnerabilities (Medium) sha256+salt, session 8h httpOnly cookie, 401/400 envelope, input validation Pydantic
Poor system performance (Medium) GIST index (PostGIS mode), index trip_record(created_at, purpose), cache route + AQI

8. Nguồn dữ liệu khảo sát — Deliverable #11 (đÃ ĐÓNG KÍN)

Bộ dữ liệu Kaggle thật đã tích hợp trở lại. File dataHN.csv (Kaggle "Vehicle at Ha Noi Dataset", 25.590 dòng × 58 cột, 9,1MB) từng bị coi là mất sau lần reset sandbox — đã được tìm lại trong thư mục tạm /tmp của máy phát triển và đưa trở lại vào repo tại backend/data/dataHN.csv (9,1MB, commit trực tiếp). Tình trạng hiện tại:

  • app/services/trend.py có 2 nhánh loader: nhánh cohort cho Kaggle (vehic → mode, OD_dist_km → distance, travtime → duration, oridist → district, purp → purpose, age → 6 nhóm tuổi) và nhánh monthly cho scaffold fallback (survey_month). dataHN.csv có mặt → nhánh cohort chạy tự động khi boot (nếu dataset_trends/vehicle_survey_responses rỗng) hoặc khi admin bấm Reprocess.
  • Trục xu hướng = 6 nhóm tuổi 0-17 · 18-25 · 26-35 · 36-55 · 56-75 · 75+ (khảo sát không có cột ngày); growth = −polyfit theo trục tuổi — mode được người trẻ dùng nhiều được coi là hướng tương lai; trend_index = 0.6×adoption + 0.4×growth.
  • Persist: 25.586 dòng sạch (lọc 4 dòng NaN/khoảng cách >80km) vào decision.vehicle_survey_responses với raw_data JSONB đủ 58 cột; 42 aggregate (6 cohort × 7 mode) vào decision.dataset_trends; 1 audit row vào core.dataset_runs với notes.periodKind="cohort".
  • Seed mở rộng 31 administrative regions (30 quận/huyện khớp oridist + "Central Hanoi") → 100% dòng khảo sát map được region_id.
  • Dashboard admin nhận periodKind=cohort → hiển thị thị phần toàn mẫu (xe máy xăng 57,4% · ô tô 26,9% · xe máy điện 5,7% …) thay vì slice nhóm cuối; nhãn KPI đổi "Tháng mới nhất" → "Kỳ dữ liệu cuối".
  • GET /api/dataset/summary là read-only (aggregate từ DB) — không chạy lại pipeline 25k dòng trên mỗi GET.
  • Fallback scaffold monthly (2.400 dòng, tools/make_dataset.py) vẫn giữ để chạy thử khi thiếu file thật.
