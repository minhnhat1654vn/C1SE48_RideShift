Điểm mạnh kiến trúc DB: một chủ sở hữu duy nhất — FastAPI tạo/migrate schema (schema.sql, idempotent), frontend là API consumer thuần (không ORM); migration layout cũ tự động (seed.py::migrate_legacy).

2. Thông tin kết nối & vận hành

Sandbox  : postgresql://postgres@127.0.0.1:5432/rideshift   (trust auth, socket /tmp)
Docker   : postgresql://postgres:postgres@db:5432/rideshift (service `db` trong compose)
Runtime  : psycopg 3 (dict_row), connection-per-request; transactional context `db.tx()`
Lệnh Công dụng
bun run db:pg:start Khởi động PG user-space (auto-initdb db/pgdata, auto-hydrate ICU symlinks)
bun run db:pg:stop / db:pg:status Dừng / tra trạng thái
bun run db:pg:start sau reset PG data dir mất → tự initdb lại; schema+seed tự tạo lúc backend boot (db.init_db() + seed.seed())
Backend boot (tự động) main.py lifespan: schema.sql → migrate legacy → seed (idempotent) → chạy pipeline dataset nếu dataset_trends trống

⚠️ Platform có thể inject DATABASE_URL=file:...custom.db — app/config.py tự fallback về DSN PostgreSQL ở trên khi URL không bắt đầu bằng postgres.

3. Sơ đồ ERD — 24 bảng · 6 schema

Xem docs/db-erd.png. Thiết kế theo DB FINAL.pdf + ERD nhóm (dbdiagram) với các điều chỉnh đã chốt của Capstone:

  • Bỏ core.users / core.vehicles — hệ thống chỉ có 2 role (guest/admin), không đăng ký/lưu tài khoản người dùng thường và không khai báo xe cá nhân. Dữ liệu xác thực đặt trong core.admins + core.admin_sessions (thay users).
  • Giữ 2 bảng pipeline dữ liệu khảo sát (không có trong DB FINAL): core.dataset_runs (audit mỗi lần chạy) + decision.dataset_trends (mode-share theo tháng) — phục vụ chức năng 34–35 (phân bố lựa chọn, xu hướng) và tiêu chí trend của TOPSIS.
  • Thêm decision.vehicle_survey_responses (theo ERD): dòng thô đã làm sạch của bộ khảo sát — raw layer cho phân tích.
  • PK toàn hệ thống là BIGSERIAL (khớp ERD); FK bigint. Chuỗi FK chính:

policy.lez_zones ──▶ policy.lez_rules ──▶ policy.vehicle_restrictions
trip.trips ──▶ trip.trip_routes ──▶ trip.trip_lez_analyses (──▶ lez_zones, lez_rules)
trip.trips ──▶ decision.recommendation_runs ──▶ decision.recommendation_scores
trip.trips ──▶ decision.impact_assessments

4. Bảng dữ liệu (24 bảng, 6 schema, snake_case số nhiều)

core (5)

  • study_areas — khu vực nghiên cứu (Hà Nội, code='HN'): code UNIQUE, area_type, country_code, geometry (GeoJSON MultiPolygon), status.
  • admins — username UNIQUE, password_hash (sha256+salt), full_name, role, status, last_login_at.
  • admin_sessions — token UNIQUE, admin_id FK CASCADE, expires_at (8h); cookie httpOnly rs_admin_session.
  • system_logs — audit: level, action (LOGIN/ZONE_CREATE/…), entity_type, entity_id, description, ip_address.
  • dataset_runs — audit pipeline: ran_at, source_file, rows_in, rows_clean, notes.

gis (3)

  • administrative_regions — 14 quận Hà Nội seeded (region_type='DISTRICT', UNIQUE(study_area, name)); trips tham chiếu qua origin_region_id.
  • road_segments / points_of_interest — trống theo thiết kế: import từ OpenStreetMap/QGIS theo 15 bước DB FINAL, app không tự vẽ.

transportation (2)

  • transportation_modes — 7 phương thức: code UNIQUE (gasoline_motorbike…), category, routing_profile (osrm), avg_speed_kmh, base_fare, cost_per_km, co2_per_km_g, avg_wait_min, accessibility_score, convenience_score, is_active, sort_order (4 cột cuối là mở rộng app cho MCDM/UI — ghi nhận deviation).
  • transportation_locations — bến xe/metro/BRT: location_type, lat/lng (số thực tiện tra cứu), geometry GEOMETRY(POINT,4326) — DB FINAL, source, status; FK mode (bus_stop → bus).

policy (4)

  • lez_zones — study_area_id FK, geometry GEOMETRY(MULTIPOLYGON,4326) nguồn chuẩn theo DB FINAL (+ GIST index), effective_from/to, status (active/inactive). API vẫn trả coordinates [[lat,lng]…] — backend suy ra từ geometry qua ST_AsGeoJSON (xem §5).
  • lez_rules — quy định theo vùng: rule_name, description, start_time/end_time (TIME), days_of_week (Mon,Tue,…), effective_from/to, status.
  • vehicle_types — taxonomy phương tiện: code UNIQUE, fuel_type, emission_standard, emission_level (0 = zero-emission, 1..6 = Euro), transportation_mode_id FK, is_default.
  • vehicle_restrictions — phán quyết theo rule × loại xe: restriction_type (banned | conditional), min_emission_level, restriction_reason.

trip (3)

  • trips — mỗi lần phân tích + lựa chọn (nguồn liệu analytics): origin_name/destination_name + origin/destination GEOMETRY(POINT,4326) origin_region_id/destination_region_id FK, origin_district, vehicle_type_id FK (xe người dùng chọn), chosen_vehicle_type_id FK + switched (quyết định thực tế), top_mode_id FK + top_score (đề xuất hàng đầu — mở rộng app cho pandas), travel_time, departure_hour, trip_purpose, preferences JSONB, distance_km, duration_min, lez_affected, avg_cost_vnd, avg_time_min. Index: created_at, trip_purpose, origin_district.
  • trip_routes — tuyến OSRM đã lưu: routing_profile, route_index, provider (osrm/estimate), distance_m, duration_sec, geometry (GeoJSON LineString).
  • trip_lez_analyses — phân tích tuyến × vùng: intersects, intersection_length_m, intersection_percentage, route_lez_status (outside/partial/within), applicable_lez_rule_id, compliance_status, compliance_reason, analyzed_at.

decision (7)

  • recommendation_criteria — 7 tiêu chí TOPSIS (admin sửa được, tổng = 100): code UNIQUE ∈ {travelTime, cost, lezCompliance, accessibility, convenience, environment, trend}, criteria_type (COST/BENEFIT), default_weight (seed: 25/20/20/10/10/10/5).
  • recommendation_runs — mỗi lần chạy TOPSIS: algorithm (TOPSIS), status, duration_ms, completed_at.
  • recommendation_scores — ma trận điểm mode × tiêu chí: raw_value, normalized_value, weight, weighted_score, final_score, rank_position; UNIQUE(run, mode, criteria). 49 dòng mỗi lần phân tích (7×7).
  • impact_assessments — so sánh phương tiện hiện tại ↔ phương án thay thế: time/cost/compliance/score của cả hai + 3 cột chênh lệch.
  • air_quality_observations — cache AQI: cache_key UNIQUE = '{lat}:{lng}' (2 số thập phân), cột aqi/pm25/pm10 (promoted) + raw_data JSONB (payload đầy đủ), observed_at; TTL 30'.
  • vehicle_survey_responses — 25.586 dòng khảo sát thật (Kaggle "Vehicle at Ha Noi Dataset", 25.590 dòng gốc): source_row (rowid), region_id (30/31 quận huyện — 100% dòng được map), area_label, trip_purpose, current_mode_id, trip_distance_km, trip_time_min, raw_data JSONB (đủ 58 cột gốc của dòng CSV).
  • dataset_trends — aggregate feed tiêu chí trend của TOPSIS + dashboard: UNIQUE(mode, month), share (0..1), trend_index (0..1), sample_count.

5. PostGIS geometry (NFR-02)

app/db.py
├── geom_write(multi)  ← INSERT/UPDATE: GeoJSON → ST_SetSRID(ST_GeomFromGeoJSON(…),4326)
├── geom_read(col)     ← SELECT: ST_AsGeoJSON(col) (GeoJSON trên wire, không hex EWKB)
└── postgis_available() ← /health hiển thị trạng thái PostGIS
  • 10 cột hình học là GEOMETRY thật (PostGIS bắt buộc) — schema.sql định nghĩa trực tiếp GEOMETRY(MULTIPOLYGON/LINESTRING/POINT,4326) + 10 GIST index (đúng DB FINAL workflow "Import into PostGIS → Create spatial indexes").
  • Volume cũ layout TEXT được upgrade in-place bởi khối cuối schema.sql: lez_zones.coordinates JSON → geometry (SET NOT NULL khi đủ ring, DROP coordinates), 9 cột TEXT còn lại ALTER TYPE với ST_GeomFromGeoJSON — exception-guarded từng cột, không mất dữ liệu, không cần re-seed.
  • Chạy trên PostgreSQL thường (không PostGIS) → schema.sql từ chối boot với thông báo rõ ràng; phân tích outside/partial/within vẫn chạy Shapely trong services/geo.py (đọc GeoJSON từ DB, kết quả like-for-like).

✅ Đã dùng dữ liệu thật. Kaggle "Vehicle at Ha Noi Dataset" 25.590 dòng × 58 cột nằm tại backend/data/dataHN.csv (9,1MB, commit trực tiếp trong repo). Bộ khảo sát không có cột ngày → trục xu hướng là 6 nhóm tuổi (0-17 · 18-25 · 26-35 · 36-55 · 56-75 · 75+); growth = −polyfit (mode được người trẻ dùng nhiều = hướng tương lai), trend_index = 0.6×adoption + 0.4×growth. Thị phần thực đo: xe máy xăng 57,4% · ô tô 26,9% · xe máy điện 5,7% · xe đạp 5,0% · đi bộ 2,1% · buýt 1,6% · taxi 1,3%. Dashboard admin tự nhận biết periodKind=cohort và hiển thị thị phần toàn mẫu. GET /api/dataset/summary là read-only (aggregate từ DB, không chạy lại pipeline).

8. Legacy

  • Họ bảng camelCase Prisma (AdminUser, TripRecord, …) — đã xoá hoàn toàn khỏi DB (schema.sql tự DROP) và khỏi code; frontend không giữ ORM nào.
  • Các layout cũ (public.admin_user, trip.trip_record, tên số ít…) — tự migrate sang 24 bảng mới bởi seed.py::migrate_legacy() rồi bị DROP.
  • db/custom.db (SQLite) — backup thời kỳ đầu, không còn được đọc.
