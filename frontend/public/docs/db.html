2. Thông tin kết nối & vận hành

Sandbox  : postgresql://postgres@127.0.0.1:5432/rideshift   (trust auth, socket /tmp)
Docker   : postgresql://postgres:postgres@db:5432/rideshift (service `db` trong compose)
Runtime  : psycopg 3 (dict_row), connection-per-request; transactional context `db.tx()`
Lệnh Công dụng
bun run db:pg:start Khởi động PG user-space (auto-initdb db/pgdata, auto-hydrate ICU symlinks)
bun run db:pg:stop / db:pg:status Dừng / tra trạng thái
bun run db:pg:start sau reset PG data dir mất → tự initdb lại; schema+seed tự tạo lúc backend boot (db.init_db() + seed.seed())
Backend boot (tự động) main.py lifespan: schema.sql → migrate legacy → seed (idempotent) → chạy pipeline dataset nếu dataset_trends trống

⚠️ Platform có thể inject DATABASE_URL=file:...custom.db — app/config.py tự fallback về DSN PostgreSQL ở trên khi URL không bắt đầu bằng postgres.

4. Bảng dữ liệu (28 bảng, 6 schema + public.City, snake_case số nhiều)

core (5)

  • study_areas — khu vực nghiên cứu (Hà Nội, code='HN'): code UNIQUE, area_type, country_code, geometry (GeoJSON MultiPolygon), status.
  • admins — username UNIQUE, password_hash (sha256+salt), full_name, role, status, last_login_at.
  • admin_sessions — token UNIQUE, admin_id FK CASCADE, expires_at (8h); cookie httpOnly rs_admin_session.
  • system_logs — audit: level, action (LOGIN/ZONE_CREATE/…), entity_type, entity_id, description, ip_address.
  • dataset_runs — audit pipeline: ran_at, source_file, rows_in, rows_clean, notes.

gis (3)

  • administrative_regions — 14 quận Hà Nội seeded (region_type='DISTRICT', UNIQUE(study_area, name)); trips tham chiếu qua origin_region_id.
  • road_segments / points_of_interest — trống theo thiết kế: import từ OpenStreetMap/QGIS theo 15 bước DB FINAL, app không tự vẽ.

transportation (2)

  • transportation_modes — 7 phương thức: code UNIQUE (gasoline_motorbike…), category, routing_profile (osrm), avg_speed_kmh, base_fare, cost_per_km, co2_per_km_g, avg_wait_min, accessibility_score, convenience_score, is_active, sort_order (4 cột cuối là mở rộng app cho MCDM/UI — ghi nhận deviation).
  • transportation_locations — bến xe/metro/BRT: location_type, lat/lng, geometry (GeoJSON Point), source, status; FK mode (bus_stop → bus).

policy (4)

  • lez_zones — study_area_id FK, geometry — ranh giới LEZ đúng DB FINAL: GEOMETRY(MULTIPOLYGON,4326) khi PostGIS bật (bản Docker), GeoJSON MultiPolygon TEXT trên sandbox (không cài được extension — cùng dữ liệu, cùng kết quả phân tích qua lớp Shapely). city_id (đa thành phố) + 4 cột vòng đời văn bản cho tab Chính sách (decision_no, issued_by, published_at, created_by); effective_from/to, status (active/inactive).
  • lez_rules — quy định theo vùng: rule_name, description, start_time/end_time (TIME), days_of_week (Mon,Tue,…), effective_from/to, status.
  • vehicle_types — taxonomy phương tiện: code UNIQUE, fuel_type, emission_standard, emission_level (0 = zero-emission, 1..6 = Euro), transportation_mode_id FK, is_default.
  • vehicle_restrictions — phán quyết theo rule × loại xe: restriction_type (banned | conditional), min_emission_level, restriction_reason.

trip (3)

  • trips — mỗi lần phân tích + lựa chọn (nguồn liệu analytics): origin_name/destination_name + GeoJSON origin/destination, origin_region_id/destination_region_id FK, origin_district, vehicle_type_id FK (xe người dùng chọn), chosen_vehicle_type_id FK + switched (quyết định thực tế), top_mode_id FK + top_score (đề xuất hàng đầu — mở rộng app cho pandas), travel_time, departure_hour, trip_purpose, preferences JSONB, distance_km, duration_min, lez_affected, avg_cost_vnd, avg_time_min. Index: created_at, trip_purpose, origin_district.
  • trip_routes — tuyến OSRM đã lưu: routing_profile, route_index, provider (osrm/estimate), distance_m, duration_sec, geometry (GeoJSON LineString).
  • trip_lez_analyses — phân tích tuyến × vùng: intersects, intersection_length_m, intersection_percentage, route_lez_status (outside/partial/within), applicable_lez_rule_id, compliance_status, compliance_reason, analyzed_at.

decision (10)

  • recommendation_criteria — 7 tiêu chí TOPSIS (admin sửa được, tổng = 100): code UNIQUE ∈ {travelTime, cost, lezCompliance, accessibility, convenience, environment, trend}, criteria_type (COST/BENEFIT), default_weight (seed: 25/20/20/10/10/10/5).
  • recommendation_runs — mỗi lần chạy TOPSIS: algorithm (TOPSIS), status, duration_ms, completed_at.
  • recommendation_scores — ma trận điểm mode × tiêu chí: raw_value, normalized_value, weight, weighted_score, final_score, rank_position; UNIQUE(run, mode, criteria). 49 dòng mỗi lần phân tích (7×7).
  • impact_assessments — so sánh phương tiện hiện tại ↔ phương án thay thế: time/cost/compliance/score của cả hai + 3 cột chênh lệch.
  • air_quality_observations — cache AQI: cache_key UNIQUE = '{lat}:{lng}' (2 số thập phân), cột aqi/pm25/pm10 (promoted) + raw_data JSONB (payload đầy đủ), observed_at; TTL 30'.
  • vehicle_survey_responses — 25.586 dòng khảo sát thật (Kaggle "Vehicle at Ha Noi Dataset", 25.590 dòng gốc): source_row (rowid), region_id (30/31 quận huyện — 100% dòng được map), area_label, trip_purpose, current_mode_id, trip_distance_km, trip_time_min, raw_data JSONB (đủ 58 cột gốc của dòng CSV).
  • dataset_trends — aggregate feed tiêu chí trend của TOPSIS + dashboard: UNIQUE(mode, month), share (0..1), trend_index (0..1), sample_count.
  • user_feedback — lý do khách không chọn phương tiện được đề xuất (user_key ẩn danh, reason ∈ cost/time/safety/weather/infrastructure/ habit/other, FK trip + mode).
  • notification_prefs — opt-in nhận thông báo chính sách theo khu vực quan tâm (user_key PK, district, opt_in).
  • user_notifications — thông báo đã sinh cho từng user_key (type ∈ lez_published/lez_active/aqi_alert, UNIQUE(user_key, type, zone_id)).

public (1)

  • City — cổng chọn thành phố (DB FINAL v1.1): id (hanoi/danang/hcm), name, studyAreaId (liên kết core.study_areas), bbox, centerLat/Lng, defaultZoom, sortOrder, active. Phường/xã đọc từ gis.administrative_regions (1 nguồn duy nhất sau khi gộp bảng Ward cũ).

5. PostGIS dual-mode (NFR-02)

app/db.py
├── enable_postgis_if_available()
│     CREATE EXTENSION IF NOT EXISTS postgis          ← thất bại → return False (sandbox)
│     ALTER TABLE lez_zones ALTER COLUMN geometry TYPE geometry(MultiPolygon,4326)
│       USING ST_Multi(ST_SetSRID(ST_GeomFromGeoJSON(geometry),4326))
│     CREATE INDEX lez_zones_geometry_gist USING gist(geometry)   ← NFR-02
├── _migrate_lez_zone_geometry() ← volume cũ (coordinates/geom) tự chuyển
│                                   dữ liệu sang geometry rồi DROP cột mirror
├── sync_zone_geometry()  ← dual-mode TEXT/PostGIS cho mọi lệnh ghi vùng
└── postgis_available() ← routers/services rẽ nhánh Shapely khi False
  • Docker/deploy: PostGIS bật → spatial query chạy trong DB (đúng chữ "PostGIS Spatial Query" của proposal §12) với GIST index.

So sánh cột chi tiết 19 bảng chung (so DB FINAL v1.0)

Khác biệt "môi trường" (không phải thiết kế):

  • BIGSERIAL ↔ BIGINT: information_schema hiển thị BIGINT, thực tế 26/26 cột PK đều có default nextval() ≡ BIGSERIAL.
  • TIMESTAMP ↔ TIMESTAMP WITH TIME ZONE: app dùng timestamptz (best practice, dữ liệu AQI đa múi giờ).
  • GEOMETRY(...) ↔ TEXT GeoJSON: sandbox không cài extension PostGIS; bản Docker nâng lez_zones.geometry đúng GEOMETRY(MULTIPOLYGON,4326) + GIST. Các cột không gian khác (trips.origin/destination, trip_routes.geometry, administrative_regions.geometry…) lưu GeoJSON TEXT portable — đọc/ghi thống nhất qua geojson_utils.
